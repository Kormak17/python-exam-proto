# Git для команды

Все в команде работают в одном репозитории и в одной ветке `develop`. Каждый пишет свой файл, поэтому правки почти не пересекаются. Чтобы видеть работу коллег, нужно забирать их изменения с сервера, а свои — пушить.

В командах ниже `АДРЕС_РЕПОЗИТОРИЯ`, `ИМЯ_ПАПКИ` и `ИМЯ_ФАЙЛА` — обозначения, которые нужно заменить своими значениями.

## Начало работы

Каждый участник клонирует общий репозиторий команды и переходит в ветку `develop`:

```bash
git clone АДРЕС_РЕПОЗИТОРИЯ
cd ИМЯ_ПАПКИ
git checkout develop
```

Если ветки `develop` ещё нет ни у кого, её создаёт один человек (`git checkout -b develop`), делает коммит и пуш, а остальные после этого выполняют `git pull` и `git checkout develop`.

## Обычный цикл работы

```bash
git pull
# ... работа над своим файлом ...
git status
git add ИМЯ_ФАЙЛА
git commit -m "Что изменилось"
git pull
git push
```

| Команда | Что делает |
| --- | --- |
| `git pull` | Забирает с сервера коммиты коллег и добавляет их к твоим файлам |
| `git status` | Что изменено у тебя |
| `git add ИМЯ_ФАЙЛА` | Подготовить файл к коммиту |
| `git commit -m "…"` | Сохранить изменения в истории |
| `git push` | Передать свои коммиты на сервер |
| `git log --oneline` | История: кто и что сохранял |

**Правило: `pull` перед `push`.** Сервер не примет твой пуш, если там есть коммиты, которых нет у тебя.

Добавляй в коммит только свои файлы. Команда `git add .` добавит всё подряд, в том числе чужие незаконченные правки и мусор — лучше называть файлы явно.

## Если пуш отклонён

Сообщение вроде `Updates were rejected because the remote contains work that you do not have locally` значит: коллега успел запушить раньше тебя.

```bash
git pull
git push
```

Если после `git pull` открылся редактор с сообщением `Merge branch …` — это нормально: сохрани и закрой его (в `nano`: Ctrl+O, Enter, Ctrl+X). Никогда не используй принудительный пуш (`--force`): он стирает работу коллег.

## Если Git сообщает о конфликте

`CONFLICT (content): Merge conflict in ИМЯ_ФАЙЛА` значит: двое изменили одни и те же строки одного файла. Если каждый работает в своём файле, это бывает редко — чаще всего с `datasets/team.csv`.

1. Открой файл в редакторе. Спорное место выглядит так:

```
<<<<<<< HEAD
твоя версия строк
=======
версия коллеги
>>>>>>> …
```

2. Оставь нужные строки (часто — обе версии), удали строки-метки `<<<<<<<`, `=======`, `>>>>>>>`.
3. Сохрани файл и закончи слияние:

```bash
git add ИМЯ_ФАЙЛА
git commit -m "Объединил правки"
git push
```

Не уверен — позови того, чьи строки в конфликте, и решите вместе.

## Файлы из прошлого репозитория

Свои вопросы второго дня и программы первого дня лежат в твоих прошлых репозиториях. Склонируй прошлый репозиторий в отдельную папку **рядом** с командным, а не внутрь него:

```bash
cd ..
git clone АДРЕС_РЕПОЗИТОРИЯ_ВТОРОГО_ДНЯ day2
git clone АДРЕС_РЕПОЗИТОРИЯ_ПЕРВОГО_ДНЯ day1
cd ИМЯ_ПАПКИ_КОМАНДЫ
```

Каждый прошлый репозиторий клонируется своей командой в свою папку: `day2` — второй день, `day1` — первый. Теперь файлы второго дня доступны по пути `../day2/…`, первого — по пути `../day1/…`. Например, дописать свои вопросы в банк команды:

```bash
tail -n +2 ../day2/datasets/my_questions.csv >> datasets/team.csv
```

Посмотреть программу первого дня, не копируя её:

```bash
cat ../day1/src/answer.py
```

Если нужной ветки там не видно, перейди в папку прошлого репозитория и выполни `git checkout develop`.

## Если Git сообщает об ошибке

| Сообщение | Что означает | Что сделать |
| --- | --- | --- |
| `not a git repository` | Ты не в папке репозитория | `pwd`, затем `cd` в папку, созданную `git clone` |
| `nothing to commit, working tree clean` | Изменений для коммита нет | Проверь `git status` и сохранён ли файл |
| `Updates were rejected` | На сервере есть чужие коммиты | `git pull`, затем `git push` |
| `CONFLICT` | Двое изменили одни и те же строки | Раздел «Если Git сообщает о конфликте» |
| `Your local changes … would be overwritten by merge` | У тебя есть несохранённые правки, а `pull` хочет изменить те же файлы | Сначала сделай коммит своих правок, потом `git pull` |
| `Please tell me who you are` | Git не знает, от чьего имени делать коммит | Обратись к стаффу |
| `Permission denied (publickey)` | Сервер не принял ключ доступа | Обратись к стаффу |
